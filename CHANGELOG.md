### Added
- **Cache disque pour les images Pexels** (Chantier 22, 2026-05-21). Régénérer un deck re-téléchargeait toutes ses images à chaque fois (~2s pour 5 images, consommation du quota gratuit 200 req/h). Nouveau cache local sous `~/.cache/aosis-deck-builder/pexels/`, indexé par hash SHA-256 de `(keyword, orientation, target_dimensions)`. Chaque `<hash[:12]>.jpg` a un compagnon `<hash[:12]>.json` avec provenance (photo id Pexels, URL, photographer, src_url, target_px, downloaded_at ISO 8601 UTC). Pas d'expiration auto (V1) — utilisateur peut vider avec `--clear-image-cache` ou `rm -rf ~/.cache/aosis-deck-builder/`. Logs explicites en stderr (`image cache HIT/MISS`). Nouveaux flags CLI sur `build_deck.py` :
  - `--no-cache-images` : bypass le cache, force fetch direct (debug/refresh)
  - `--clear-image-cache` : vide le cache et exit (utilitaire de maintenance)
  
  Picsum n'est pas caché (déjà déterministe par seed et gratuit, latence ~200 ms). Helpers ajoutés : `set_cache_enabled(bool)`, `clear_image_cache() -> int`. Override d'env `AOSIS_IMAGE_CACHE_DIR` pour les tests. Mesures sur `test_migration_cloud.pptx` (5 images Pexels) : **1.68s cold → 1.01s warm (-40 %)**, économie réseau totale sur les régénérations. Backup `image_engine.before-chantier22.py`. **80 passed, 1 skipped** (+3 tests : `test_image_cache_hit_avoids_network_call`, `test_image_cache_miss_calls_pexels`, `test_image_cache_can_be_cleared` + 1 test existant adapté à la nouvelle signature `_fetch_pexels` retournant `(bytes, metadata)`).

### Fixed
- **KPI cards : positionnement vertical dynamique + anti-débordement** (Chantier 20, 2026-05-21). Trois bugs visuels résiduels après C19 sur `cloud_computing_2026_v3.pptx` :
  - **canvas_blank kpi_card avec label long** : la disposition fixe `value=60% top / label=35% bottom` ne tenait pas compte de la hauteur réelle du label (10pt uppercase pouvant wrap sur 2-3 lignes). Sur les cards courtes (asym 4+ blocs, 0.58-1.07" tall) le label dépassait par le bas (slide 10 V3 : 3ᵉ card "PAYBACK INVESTISSEMENT" 0.27" de label dispo pour 1 ligne réelle).
  - **kpi_with_chart valeurs avec chars larges 'M€'** : le helper C19 retournait 24pt floor pour "4.2 M€" sur shape 1.00"×0.47" — mais 24pt × 6 chars × 0.55 ≈ 79pt > 72pt de largeur disponible, donc "M€" wrappait à la ligne 2.
  - **slide 16 V3 (6 blocs asym, cards 0.58")** : value "M1" (24pt floor) + label "AUDIT + CARTOGRAPHIE..." n'avait jamais la place de coexister verticalement.

  **Solution** : nouveau helper `_cb_kpi_card_dynamic_layout(value, label, rect, override_size_pt, floor_pt=14)` qui retourne `(value_size_pt, value_rect, label_rect)`. Estime la hauteur du label (uppercase, char width 0.60 × pt, line height 1.25), calcule le budget vertical pour la value, choisit la taille via `_compute_max_kpi_font_size` avec `floor_pt=14`, centre verticalement value+label quand il y a de la place, tasse depuis le top sinon. Anti-overflow garanti : `label_rect.bottom ≤ card.bottom - pad`. `_cb_render_kpi_card` consomme directement les rects retournés. Idem pour `kpi_with_chart` (passage `floor_pt=14` dans l'appel `_compute_max_kpi_font_size`) afin d'éviter le wrap sur shapes étroites.

  **Résultats V3** : slide 5 (Adoption, asym) **48pt** uniforme (vs 36pt C19), slide 10 (Statu quo, asym) **48pt** uniforme avec last card B=4.35" (footer reserve respectée), slide 15 (Piliers 2×2) **60pt** XXL maintenu, slide 16 (6 blocs asym 0.58" cards) **14pt** floor avec value above label, zero overlap.
